# Smart Unreal Localization — Посібник користувача

Повний опис можливостей за робочими процесами. English version:
[USER-GUIDE.md](USER-GUIDE.md).

**Встановлення.** Розпакуйте zip релізу в теку, куди можна писати (Документи,
Робочий стіл — не Program Files: експорт і автозбереження за замовчуванням
лягають поруч з exe) і запустіть `SmartUnrealLocalization.exe`. Середовище .NET
вже всередині exe, більше нічого не потрібно. Exe не підписаний, тож Windows
SmartScreen може попередити при першому запуску (**Докладніше → Виконати все одно**).
Цей посібник є також у програмі: **Довідка → Документація**; **Довідка → Перевірити оновлення** питає репозиторій проєкту про новіший реліз (лише коли ви натиснете; нічого не завантажується — новішу версію пропонують як сторінку, яку можна відкрити); **Довідка → Ліцензії**
показує ліцензію MIT програми й усі сторонні компоненти з текстами їхніх ліцензій.

## 1. Відкриття файлів

- **Файл → Відкрити (Ctrl+O)**, перетягування файлу на вікно чи exe або нещодавній
  файл — на стартовому екрані чи в **Файл → Останні файли**.
- Кожен файл відкривається у **вкладці** зі своїми правками, історією undo та
  крапкою незбережених змін; вкладки можна закріпляти, перетягувати і вони
  відновлюються при наступному запуску.
- Для `.locres` пілюля заголовка показує версію формату
  (напр. `Game.locres · en · locres v3 (CityHash64)`). Namespace і Key —
  окремі колонки. Записи з порожнім значенням приховані за замовчуванням —
  перемикач **Вигляд → Показувати порожні ключі** (у файлі вони зберігаються
  завжди).
- У `.po` ключем є msgctxt; файли, експортовані цією програмою (або Unreal),
  несуть namespace всередині msgctxt як `Namespace,Key` і розбираються
  автоматично.
- **PO-фіделіті**: коментарі перекладача (`#`, `#.`, `#:`), прапори та
  plural-записи переживають імпорт → редагування → експорт. Грід редагує
  **форму 0** множини; решта форм зберігаються недоторканими. `fuzzy`-переклади
  імпортуються з попередженням у лозі, а прапор знімається автоматично після
  редагування рядка (семантика Poedit). Застарілі (`#~`) записи відкидаються.

## 2. Редагування

- **Скопіювати частину клітинки:** затисніть ліву кнопку на клітинці Key, Source чи Target, проведіть по тексту й натисніть **Ctrl+C**. Подвійний клік виділяє слово в Source (тег — одне слово) і весь ключ у Key. Клік, як і раніше, вибирає рядок; подвійний клік по Target відкриває його редагування.

- Редагується лише колонка **Target**. Подвійний клік, F2 або Enter відкриває
  редактор. У ньому:
  - **Enter** підтверджує й переходить на наступний рядок (Enter там відкриває його);
    **Ctrl+Enter** підтверджує й лишає на місці; **Tab** підтверджує й іде далі.
  - **Shift+Enter** — новий рядок у тексті; **Esc** скасовує правку.
  - **Ctrl+Z / Ctrl+Y** скасовують і повертають лише набране в редакторі — інших
    рядків вони не чіпають. Поза текстовим полем вони скасовують правки таблиці.
  - **Ctrl+T** вставляє в редактор Source рядка (Ctrl+Z повертає як було).
  - Подвійний клік по слову виділяє його.
- **Скасувати / Повторити (Ctrl+Z / Ctrl+Y)** покриває все, включно з AI-батчами
  (1 батч = 1 крок) та імпортом цільового locres (1 крок). Історія — до 100 записів
  на вкладку.
- **Скопіювати джерело → переклад** (Ctrl+T — поточний рядок, Ctrl+Shift+T — всі
  вибрані), операції з колонкою через ПКМ по заголовку Target, копіювання
  всієї таблиці як TSV для Excel.
- **Вибрані рядки** (чекбокс у заголовку / по рядках) відкривають меню
  «Позначено: N» — копіювання/вставка/вирізання/очищення лише для них.
  При вставці кількість рядків у буфері має збігатися з кількістю галочок.
- Виділення належить **усьому файлу**: фільтр змінює те, що *видно*, а не те,
  що *позначено*. `Позначено: N` у статус-барі рахує всі позначені рядки файлу
  — саме на них подіє будь-яка дія — і додає `(N видно)`, коли частину
  виділення ховає активний фільтр. Єдиний контрол, що зважає на фільтр, —
  чекбокс у заголовку: він позначає й знімає позначки з того, що на екрані.
- **Пошук (Ctrl+F) / Заміна (Ctrl+H)** — збіги підсвічуються в Source і
  Target; фільтр «Лише збіги пошуку» лишає тільки рядки зі збігами — усі, скільки б їх не було.
  Надто широкий запит (часте слово по тисячах рядків) дає більше збігів, ніж
  можна обійти вручну, тому навігація зупиняється на 5 000, і лічильник це
  показує: `3 / 5000+ (of 128 431)`. Число після "of" — справжня загальна
  кількість; звузьте запит, щоб працювати з усіма.

## 3. Рев'ю

- ПКМ по рядку → **Позначити схваленим / Позначити відхиленим / Скинути перевірку**. Іконки статусу та
  фільтри рев'ю — у нижній панелі.
- **Коментарі** — кнопка з бальбашкою на рядку відкриває вільну нотатку рев'ювера.
  Коментарі — метадані: зберігаються в sidecar-файлі поруч із файлом і
  ніколи не потрапляють в експорти. Є окремий фільтр закоментованих рядків.
- Стан рев'ю і коментарі прив'язані до файлу (за повним шляхом) і
  переживають перезапуск.

## 4. AI-переклад

Налаштовується в **Налаштуваннях**: пресет провайдера (Gemini / OpenAI /
Anthropic / OpenAI-сумісний), API-ключ, модель, опційний base URL, розмір
батча, кешування промпта, паралельні запити, автоповтор, а також опційне
обмеження частоти (мінімальна пауза між запитами до ШІ — для жорстких
лімітів провайдера).

API-ключ зберігається **зашифрованим** (Windows DPAPI, прив'язка до вашого
акаунта Windows на цій машині) — у `config.json` він ніколи не лежить
відкритим текстом, тож бекап чи копія конфігу його не зливають. Зворотний
бік: ключ не переноситься — на іншому ПК чи акаунті Windows просто введіть
його в Налаштуваннях ще раз.

- Панель **AI переклад**: мовна пара, область («Усі рядки» / «Лише позначені
  рядки таблиці» / «Лише неперекладені»), додатковий промпт для контексту ("Sci-Fi гра, формальний тон").
- Область **Лише позначені** показує поруч, скільки це рядків — `(12)` — і
  оновлюється, поки панель відкрита, тож позначати рядки й відкривати панель
  можна в будь-якому порядку. Якщо не позначено нічого, запуск відхиляється з
  повідомленням — програма ніколи не переходить мовчки на переклад усього файлу.
- Вбудований захист: `<Теги>` і `{плейсхолдери}` зберігаються; таг-only
  рядки копіюються без відправки; однакові source перекладаються один раз і
  поширюються; **Translation Memory** повторно використовує переклади для
  мовної пари; **захищені терміни** (глосарій) не перекладаються. Пам'ять кожної
  пари — окремий файл `translation_memory_{from}_{to}.json`; **Інструменти →
  Відкрити теку Translation Memory** показує, де вони лежать.
- **Надсилати з коментарями** (типово увімкнено): рядки з коментарями надсилають
  нотатку як інструкцію для цього рядка і обходять TM, щоб нотатка
  гарантовано спрацювала.
- **Додатковий контекст** (обидві опції типово вимкнені; вся панель пам'ятає
  свої налаштування до закриття програми — у конфіг нічого не пишеться):
  - *Надсилати Key рядка* — змістовні ключі (`BTN_Cancel`, `Quest_Title`)
    підказують ШІ, де з'являється текст; GUID-подібні ключі пропускаються
    автоматично. Рядки, що надсилають ключ, свідомо **оминають Translation
    Memory і повторне використання за source**: одне англійське слово під
    різними ключами може потребувати різних перекладів (`Weapon.Charge` —
    «Зарядити», `Store.Charge` — «Плата»), тому кожен такий рядок
    перекладається окремо — точніше, але дорожче. Їхні результати пишуться
    в TM як key-aware записи (ключ + source → переклад) і повторно
    використовуються лише при ТОЧНОМУ збігу ключ + source — той самий рядок
    на тому самому місці, тож повторні прогони безкоштовні без втрати
    точності. Рядки без надісланого ключа (напр., GUID) працюють з TM як
    звичайно.
  - *Довідковий переклад* — оберіть другий .locres/.csv/.po ТІЄЇ Ж гри
    (наприклад, її польську чи російську локалізацію). Рядки звіряються за
    ключем, і ШІ отримує явні ролі: АКТИВНИЙ файл — **Primary Source**
    (авторитетний оригінал), обраний файл — **Reference Translation** —
    підказка сенсу, що знімає неоднозначність (рід, число, частина мови),
    але ніколи не перемагає оригінал. Позначте якість довідкового перекладу
    (Офіційний/людський, Спільнота, Машинний, Невідомо) — так ШІ знає,
    наскільки йому довіряти: до машинного ставиться обережно. Для csv/po
    можна вибрати, звідки брати текст: колонка Source чи Target. Перед
    запуском програма звіряє ключі й показує статистику — рядки без пари
    просто перекладаються з Primary Source. Довідковий файл ніколи не
    змінюється. Повторне використання враховує довідку: два рядки з однаковим
    source І однаковою довідкою перекладаються один раз і повторюються
    (auto-repeat), але якщо довідка дає двом однаковим source *різні* значення
    — вони перекладаються окремо й ніколи не копіюються наосліп один поверх
    одного, і в послідовному, і в паралельному режимі.
- Панель **Мультипереклад**: N цільових мов, тека виводу, промпти на мову —
  кожна мова перекладається окремою фазою і пишеться у
  `<тека>/<локаль>/<файл>` у форматі вкладки. Для `.locres` файл будується
  зі скелета документа сесії — байт-коректно для гри, без проміжних файлів.
- **Історія промптів** (кнопка «годинник зі стрілкою» в лівій панелі або
  Вигляд → Історія промптів): кожен окремий промпт, який надіслала програма —
  інструкції, а не ваші рядки — з AI-перекладу, мультиперекладу та AI QC. Рядок
  називається `номер_файл_дата_час_режим`, напр.
  `1_Game.locres_11/10/2026_17:26_SingleTranslation`; натисніть його, щоб
  розгорнути текст на місці (можна відкрити кілька), **Копіювати** бере весь
  промпт, а текст можна виділити й скопіювати частину. Однаковий промпт для
  того самого файлу в тому самому режимі зберігається один раз. Промпти —
  окремі файли в `prompts/single`, `prompts/multi` і `prompts/qc` у теці
  профілю; кнопка з текою в заголовку панелі відкриває її.

## 5. Збереження та експорт

- **Зберегти (дискета)** — пише поточний формат у підтеку `Export_*` з
  таймстемпом у вашій **теці експорту**. Вкладка `.locres` пише справжній
  locres через вбудований рушій: атомарно, порожні Target зберігають
  оригінальний текст, у статусі — скільки перекладів застосовано.
- **Зберегти як (Ctrl+Shift+S)** — поведінка налаштовується
  (Налаштування → Файли → *Поведінка Save As*):
  - **Завжди запитувати** — системний діалог; обраний шлях шанується точно.
  - **Тека Export** — тихе збереження в теку експорту.
  - **Як автосейв** — тихе збереження в теку автозбереження.
- **Експорт (Ctrl+E)** — одразу в `.locres`. CSV-вкладка без бази запитає
  семпл `.locres`, який визначає версію формату.
- **Автозбереження** — кожні N хвилин (Налаштування) у підтеки `AutoSaved_*`
  **теки автозбереження**. Автосейви — резервні копії: вони не знімають
  крапку незбережених змін.
- **Якщо програма впаде**, вона спершу запише незбережені правки кожної
  відкритої вкладки в підтеку `Recovered_*` теки автозбереження, у форматі
  самої вкладки, і лише тоді закриється. Під час наступного запуску в лозі
  буде, коли це сталося, де врятовані файли і де звіт (див. Troubleshooting).

## 6. Оновлення гри — Об'єднати з новою версією

Файл → **Об'єднати з новою версією** переносить ваші переклади в оновлену збірку гри.

**Спершу обираєте старий файл** — `.locres`, `.csv` або `.po`. Короткий
діалог пояснить, як саме цей файл зіставлятиметься, і лише після вашого
підтвердження з’явиться другий вибір — `.locres` нової версії.

### Переклад переноситься лише там, де це можна довести

Збіг ключа сам по собі не є доказом. Під тим самим ключем у новій
збірці може бути переписана англійська, і старий рядок тоді поїде в гру
зі смислом, якого вже немає. Тому збіг ключа підтверджується:

| Старий файл | Чим підтверджується збіг |
|---|---|
| `.locres` | **SourceStringHash** — відбиток англійського оригіналу, який перекладений locres несе, але показати не може. Інший відбиток = оригінал змінився. |
| `.csv` / `.po` **з колонкою перекладу** | Сама колонка **source**, порівняна з текстом нової версії. Найнадійніше, бо старе формулювання є під рукою. |
| `.csv` / `.po` з однією колонкою | Підтверджувати нічим — лише ключі. |

Рядки, що не пройшли перевірку, лишаються **неперекладеними** — тож звичайний
фільтр *Без перекладу* і область «Лише неперекладені» в AI перекладі їх дістають.

Саме тому CSV/PO-експорт попереднього перекладу — кращий вхід: у ньому
оригінал стоїть поруч із перекладом, тож перевірка порівнює справжній текст,
а не відбиток — і вона працює, навіть якщо старому locres хеші перерахував
чужий інструмент.

### Звіт — до того, як щось буде записано

Ви завжди спершу бачите, що зійшлося:

```
Merge — перенесено 18 973 з 20 300 рядків
Зіставлено за ключем + відбитком оригіналу (SourceStringHash).
  З "old.locres" у структуру "new.locres".
  18 973 з 20 300 рядків отримають свій переклад назад.
  1 200 НЕ перенесено: оригінал змінився в цьому оновленні.
  800 ключів нові в цій версії.
  500 ключів зі старого файлу зникли в новій версії.

  [Скасувати]  [Зіставити лише за ключем]  [Перенести 18 973 перекладів]
```

**Зіставити лише за ключем** — це аварійний вихід. Суворе правило може
законно не зіставити **нічого** — старий файл із перерахованими хешами
виглядає зміненим на 100% — і тихе застосування такого результату
замінило б готовий переклад порожнім. Якщо перевірку пройшло менше
половини збіглих ключів, діалог про це попередить.

Щоб зробити зіставлення лише за ключем постійним — **Інструменти → Розширені
налаштування**.

### Після merge

У таблиці **оригінал нової версії в Source** і **перенесений переклад у
Target** — як у будь-якого іншого файлу, тож лічильники, фільтри й QC
означають те саме, що й завжди. Підсвітка рядків:

- 🟩 **зелений** — ключ, новий у цій версії,
- 🟪 **фіолетовий** — оригінал змінився, тому старий переклад не перенесено.

Обидві категорії порожні, тож **AI переклад з областю «Лише неперекладені» покриває
рівно ту роботу, яку залишив merge**. У панелі Фільтр також з’являється
секція *Результати merge* із пунктом **Нові ключі**, якщо їх треба окремо.

**Збережіть до закриття програми.** Доки цього не зроблено, результат живе
лише в цій сесії; після перезапуску вкладка перечитає файл нової версії,
у якому перекладів немає.

**Що з ключами, які оновлення прибрало?** Вони свідомо відкидаються —
оновлена гра їх не читає. Переклади не втрачені: тримайте старий файл
як архів (лог повідомляє, скільки відпало), а Translation Memory тримає
кожен переклад за текстом оригіналу.

## 7. Імпорт цільового locres

Файл → **Імпорт цільового locres**: завантажити другий `.locres` як переклад для вже
відкритого файлу, зіставляючи за (namespace, key). Увесь імпорт — один крок скасування.

Записується все, що імпортований файл має для збіглого ключа, **включно з
перекладами, ідентичними оригіналу**. Рядки з самих тегів, числа, власні назви та
короткі слова, однакові в обох мовах, — це справжні переклади; коли їх
відкидали, такі рядки читались як неперекладені.

Лог повідомляє, що сталося, тож несподіваний результат можна перевірити:

```
📥 Import Target: "Game.uk.locres" — зійшлося за ключем 12 900 з 13 476
   рядків, записано 12 431 перекладів.
ℹ️ Import: 469 рядків уже мали саме такий переклад — змінювати нічого.
ℹ️ Import: 1 204 переклади збігаються з оригіналом.
ℹ️ Import: 576 рядків тут не мають ключа в імпортованому файлі.
```

Рядки, для яких в імпортованому файлі немає ключа, лишаються як були — їх ніколи
не очищають. Запис, який там є, але порожній, теж не імпортується: імпортувати
нічого, а затерти наявний переклад порожнечею було б гірше. Якщо не зійшовся
жоден ключ, програма про це скаже й нічого не змінить — зазвичай це означає, що
файли від різних версій гри.

Імпортовані рядки одразу проходять валідацію, тож переклад, чиї теги більше не
відповідають оригіналу, видно відразу, а не після F8.

## 8. Валідація

Відкриття файлу запускає легкі валідатори по кожному рядку, і ще раз через
300 мс після кожного редагування:

| Перевірка | Рівень | Що ловить |
|---|---|---|
| Теги | Error | `<b>`, `[b]`, `[/i]`, `[color=red]`, `[PLAYER_NAME]` зникли, з'явились зайві або з помилкою. Квадратні дужки вважаються розміткою лише коли виглядають як **код** — закривний тег, `=` чи `_` усередині, або жодної великої літери. Слово з великої в дужках (`Mysterious Orb [Charged]`, `[NEW]`) — це ТЕКСТ, який треба перекладати, як і речення в дужках (`[Сторінка подерта]`). |
| Токени | Error | `{count}` зник, продубльований або з перекладеною назвою. |
| Плейсхолдери | Error | `%s`, `%d`, `%1$s`, `%.2f` зникли або з'явились зайві — гра підставить не те значення або впаде на форматуванні. |
| Множина | Error | `\|plural(one=…, other=…)` зник або має менше форм, ніж оригінал. Більше форм — це правильна робота, не позначається. |
| Змішані абетки | Warning | Латинська літера всередині кириличного слова — гліф той самий, рядок зламаний. |
| Вміст | Warning | Фраза перекладена цифрами, або оригінал із самих символів змінено. |
| Сміття моделі | Error | `Translation:` чи лапки навколо всього рядка, що прийшли від моделі, а не з оригіналу. Виправлення їх прибирає. |
| Переноси рядків | Warning | Зникли всі переноси або з'явилися ті, яких в оригіналі немає. Інша кількість сама по собі (перекомпонований текст) не позначається. |
| Інша мова | Warning | Літери чи часті слова іншої мови, що лишилися в тексті. Потрібна мова файлу (з його теки, напр. `uk`); якщо вона невідома, перевірка мовчить. Правильні слова можна додати у винятки. |
| Захищений термін | Warning | Термін зі списку захищених є в оригіналі, але зник у перекладі. |
| Термінологія | Warning | Спрацювало ваше правило `неправильно=правильно`; виправлення його застосовує. |
| Пробіли | Info | Крайові пробіли й переноси не збігаються з оригіналом **в обидва боки** — і зайві, і втрачені. Втрачений пробіл на початку склеює два слова в рантаймі. |
| Пунктуація | Info | Кінцевий `. ! ? … : ;` з оригіналу зник або інший. |
| Довжина | Info | Переклад більш ніж удвічі довший за оригінал. |
| Дублікати | Info | Той самий оригінал перекладено кількома способами. У спливному вікні нотатки можна пройти всі переклади цього тексту (◂ ▸) і натиснути **Використати цей переклад для такого самого тексту**: рядки, які зміняться, показуються «до → після», записуються лише залишені вами, одним кроком undo. Працює на відкритті та по F8. |

Чотири рядки рівня **Info** — це нотатки, і кожну можна вимкнути в **Налаштування →
Перевірка**. **Пробіли типово вимкнені**: на реальних файлах вони спрацьовують на
сотнях рядків, з якими все гаразд. Перевірки рівнів Error і Warning працюють завжди.
Перемикач одразу діє на всі відкриті файли.

**Перевірити теги** запускає валідацію на вимогу.

**Жодне виправлення не записується, доки ви його не побачите.** Лампочка в клітинці,
**Виправити** у вкладці «Проблеми» і **Виправити все** відкривають перегляд: кожна показана «було» і «стане», змінені слова підсвічені, а змінений пробіл як `·`. Зніміть галочку з того, що не потрібно, — решта застосується кроком скасування. Виправлення, яке зламало б щось інше в рядку (нову помилку попередження), не пропонується зовсім, і перегляд каже, скільки таких відкладено., який ви змінили після відкриття перегляду, пропускається, а не перезаписується.

Валідатори і QC користуються **однаковими**
визначеннями тега, плейсхолдера та кінцевої пунктуації, тож ці дві системи
не можуть розійтися в тому, чи рядок зламаний.

**Дублікати — це нотатка, а не помилка.** Коли той самий Source перекладено
кількома способами, кожен такий рядок отримує запис рівня Info, який називає
інші переклади та ключі, де вони лежать, — щоб ви могли піти й порівняти.
Кнопки «звести все до одного» свідомо **немає**: кожен ключ має свій контекст,
а файл, зібраний з кількох мов, відрізняється навмисно — масова кнопка тут
тихо стерла б свідому роботу. QC повідомляє про те саме так само, нотаткою Low.

Проблеми видно як відтінки рядків
(червоний = помилка, жовтий = попередження), смужку на лівому краю,
лічильники з фільтрами в статус-барі та вкладку «Проблеми» (даблклік —
перехід до рядка). Рахують вони різне: лічильник у статус-барі рахує **рядки**,
кожен за його найсерйознішою проблемою, а вкладка показує **кожну проблему** —
рядок із двома попередженнями дає 1 у лічильнику і 2 у вкладці. Клік по
лічильнику — показати лише його рядки; правий клік — очистити цей статус у
позначених рядках.

### Мова інтерфейсу

Кнопка 文A на верхній панелі, ліворуч від сонця/місяця — або Налаштування →
Мова інтерфейсу, це те саме. Програма постачається 15 мовами: English,
Українська, Deutsch, Español, Français, Italiano, Polski, Português (Brasil),
Русский, Türkçe, Tiếng Việt, 简体中文, 繁體中文, 日本語, 한국어. Зміна застосовується
одразу — усе вікно перемальовується новою мовою, без перезапуску й без втрати роботи.

Кнопку винесено нагору свідомо. Якщо програма відкрилася мовою, якої ви не
читаєте, знайти потрібний рядок у налаштуваннях, написаних тією ж мовою, — саме
те, чого зробити не вийде. Тому вихід позначений символом, він на тому самому
місці в усіх мовах, а в меню кожна мова названа так, як вона називає себе сама.

Частина слів свідомо лишається англійською в усіх мовах: `locres`, `namespace`,
`key`, `Source`, `Target`, `SourceStringHash`, `QC`, `Translation Memory`, `MCP`,
назви форматів і всі клавіатурні скорочення. Вони називають річ у файлі або
елемент на екрані, тож переклад змусив би інтерфейс, цю довідку й форуми
розійтися. Повний список — у `Localization/GLOSSARY.md`.

**Як додати мову самому.** Скопіюйте `Localization/strings.en.json`, перекладіть
значення, назвіть файл `strings.<код>.json` і покладіть назад у ту саму папку —
програма підхопить його на наступній збірці без жодної зміни коду. Додайте
`_meta.name` (як мова називає себе — для списку вибору) і `_meta.fontFamily` /
`_meta.fontMono`, якщо потрібен інший шрифт. Повідомлення з числами використовують
ключі множини (`key.one`, `key.few`, `key.many`, `key.other`) — вкажіть ті форми,
які ваша мова справді має; `dotnet test` скаже, яких бракує, і заразом перевірить
плейсхолдери, скорочення та захищені терміни.

## 10. QC — контроль якості

Кнопка **QC** у лівій панелі перевіряє **вже перекладений** файл, а не
перекладає його заново. Це **перевірка ШІ**: налаштована модель читає кожен
рядок і або підтверджує його, або пропонує виправлений. Власних правил-перевірок
у QC немає — плейсхолдери, теги, переноси, залишки мови оригіналу, сліди
відповіді моделі, захищені терміни й ваша термінологія перевіряються **наживо
валідатором** під час редагування (розділ 8), тож вони вже на екрані ще до того,
як ви відкриєте цю панель.

**Як це працює**

1. Відкрийте файл для перевірки — **активна вкладка і є файлом під
   перевіркою**, і панель показує його назву. Далі вкажіть ролі файлів:

   | Роль | Звідки береться | Обов'язково |
   |---|---|---|
   | **Переклад, який перевіряється** | Source *або* Target активного файлу | так |
   | **Оригінал**, з якого перекладали | Source активного файлу або другий файл (за ключем) | так |
   | **Додаткова мова** | третій файл | ні — додатковий контекст для моделі |

   `.locres` містить **одну** мову, тож відкритий перекладений `.locres` кладе
   свій текст у **Source**, а Target лишається порожнім. Це нормальний випадок:
   оберіть *«Переклад для перевірки в колонці: Source»*, додайте файл мовою
   оригіналу — і QC запише прийняті виправлення в порожній Target. Збереження
   тоді дає виправлений файл, бо порожній Target за контрактом лишає базове
   значення. CSV і PO можуть уже містити обидві колонки — панель це визначає
   й одразу обирає Target.

   Після вибору файлу оригіналу панель показує, скільки ключів зійшлося
   (`12 480 із 12 500 рядків знайдено`), тож файли з різних версій гри видно
   ще до запуску, а не після.
2. Оберіть обсяг (усі рядки чи лише позначені) і мовну пару.
3. **Рядки для перевірки** — надсилається кожен рядок в обсязі, крім тих, які
   відсіюють ці перемикачі. Біля кожного видно, скільки рядків він відсіює
   (`−312`), а рядок під ними показує, скільки рядків і запитів коштуватиме
   запуск, ще до того, як ви щось витратите:

   | Перемикач | За замовчуванням | Відсіює |
   |---|---|---|
   | Пропускати рядки без тексту | увімк. | рядки без перекладу або без оригіналу для порівняння |
   | Пропускати рядки, перенесені автоматично | увімк. | рядки лише з тегів, чисел чи плейсхолдерів — скопійовані як є, перекладати нічого |
   | Пропускати рядки, ідентичні оригіналу | увімк. | імена, коди, неперекладені копії |
   | Пропускати схвалені рядки | увімк. | рядки, які рецензент уже позначив «Схвалено» |
   | Лише рядки, позначені валідатором | вимк. | усе, на чому валідатор нічого не знайшов — найдешевша перевірка |

   Перемикачі зберігаються в налаштуваннях програми.
4. Натисніть **Запустити AI-перевірку**. Поступ, влучання в кеш і відхилені
   виправлення видно по ходу; **Зупинити** зберігає все вже перевірене.
5. Рядки з пропозицією отримують **значок QC** біля іконки коментаря.
   Клацніть — побачите повну різницю з підсвіченими зміненими словами — і
   оберіть **Fix** (застосувати) чи **Keep** (лишити; більше не
   пропонуватиметься).
6. Масово: **Виправити всі** / **Виправити позначені** з'являються у
   панелі фільтрів, *поки відкрита панель QC*. Спершу вони відкривають те саме
   вікно перегляду, що й виправлення валідатора — кожна зміна «до → після»,
   зніміть галочку з того, що не треба, — а решта стає ОДНИМ кроком
   скасування (Ctrl+Z).
7. **CSV-звіт** експортує лише рядки, де є пропозиції.
8. Вкладка **QC** внизу — на одному рівні з «Проблемами» та «Журналом», видима
   лише поки є відкриті пропозиції — показує їх **згрупованими за категоріями**
   і згорнутими. Клац по заголовку — розгорнути; **Виправити N** переглядає й
   застосовує цілу категорію, **Виправити все** на панелі — усі пропозиції, де
   є заміна. Наведення показує заміну (`− було` / `+ стало`), даблклік —
   перехід до рядка в таблиці.

   Список поводиться як список «Журналу»: клац — виділити, Ctrl+клац / Shift+клац —
   кілька, **Ctrl+A** — усе, **Ctrl+C** (або права кнопка → Копіювати) — скопіювати
   як текст із табуляціями: ключ, серйозність, категорія, опис, запропонована
   заміна. Він також слідує за таблицею: коли ви обираєте рядок із пропозицією,
   тут виділяється його запис; вкладка «Проблеми» робить те саме для знахідок
   валідаторів.

**Що робить модель** — вона не перекладає заново; для кожного рядка відповідає
*ok* або *fix* з виправленим рядком, суворим JSON (тож пояснення фізично не
може потрапити в переклад). Вона отримує оригінал, поточний переклад і (якщо ви
його завантажили) той самий рядок третьою мовою. Ваш текст побажань передається
як опис *очікуваного* результату, а не як команда перекладати. Кожне
запропоноване виправлення потім перевіряється локально й **відхиляється**,
якщо ламає плейсхолдер, тег, перенос, кінцевий обрив «...» чи крайові пробіли —
лічильники показують, скільки відхилено.

**Контроль витрат** — вердикти кешуються для мовної пари за моделлю, версією
промпта, вашими побажаннями і текстами рядка; повторний запуск QC після
виправлення кількох рядків платить лише за те, що справді змінилось. «Зупинити»
безпечне: скасований запуск зберігає всі вердикти, за які вже заплачено, а
кеш пишеться по ходу прогону — тож закриття програми посеред перевірки теж
нічого не втрачає. Розмір батча й паралельність — у власному діалозі
**Налаштування QC…** панелі QC, окремо від налаштувань швидкості перекладу.

**Ваша термінологія і винятки** — у тому ж діалозі є два списки, якими
користується **валідатор**: **Термінологічні виправлення** (рядки
`неправильно=правильно`, напр. `пролом=пробоїна`) — хибний термін позначається,
а заміна пропонується як виправлення з переглядом — і **Винятки витоку**:
слова, які перевірка залишків мови постійно позначає, хоча вони правильні
(імена персонажів, запозичення). Збереження діалогу заново перевіряє відкриті
файли.

Пропозиції зберігаються у сайдкарі поруч із файлом (`<файл>.qc.json`), тож
незавершений перегляд переживає закриття програми чи перезавантаження ПК. У
переклади нічого не пишеться, доки ви не натиснете Fix; якщо рядок змінився
після перевірки, його застаріла пропозиція позначається й не застосовується.
Якщо виправлення покриває лише частину знайденого, значок лишається з тим, що
не вирішено. **Очистити** прибирає весь перегляд для файлу (спитає
підтвердження) — спершу експортуйте CSV-звіт, якщо пропозиції ще потрібні.

**Як отримати виправлений файл.** Коли переклад перевірявся в Source, прийняті
виправлення лежать у Target — дві колонки для однієї мови. Збереження в
`.locres` це вже вирішує (порожній Target лишає базове значення). Для CSV чи PO
є **Файл → Зберегти як одну мову**: він пише одну колонку за тим самим
правилом — Target там, де виправлення прийнято, Source в усіх інших рядках.
Звичайне **Зберегти як** і далі пише обидві колонки без змін — його й обирайте,
коли віддаєте файл перекладачеві.

## 11. MCP-сервер — керування програмою з AI-чату

Увімкніть **Налаштування → MCP-сервер**, і будь-який MCP-клієнт (Claude Desktop,
Claude Code, ChatGPT Codex, Antigravity, …) зможе керувати ЗАПУЩЕНОЮ
програмою: відкривати файли, читати рядки, записувати переклади (з валідацією
тегів; один батч = один крок скасування), запускати/зупиняти вбудований
AI-переклад, зберігати. Якщо в клієнті модель за підпискою — вона може
перекладати рядки САМА через `get_rows` → `set_translations`, без витрат
вашого API-ключа.

Все локально: міст — це named pipe на цьому ПК, видимий лише вашому акаунту
Windows. Вікно програми має бути відкритим; на диск нічого не пишеться до
`save_current` (а він зберігає в теку експорту з часовою міткою — оригінальний
файл ніколи не перезаписується).

У клієнті вкажіть виконуваний файл програми з аргументом `--mcp`:

**Claude Desktop — в один клік**: натисніть **Створити розширення Claude
Desktop (.mcpb)…** у Налаштування → MCP-сервер. Поруч із програмою з'явиться
`SmartUnrealLocalization.mcpb` — подвійний клік (або перетягніть у Claude
Desktop → Settings → Extensions), і підключення готове без правки конфігів.
Перестворіть файл, якщо перемістите програму. Ручна альтернатива —
`claude_desktop_config.json` (Settings → Developer → Edit Config):

```json
{
  "mcpServers": {
    "smart-unreal-localization": {
      "command": "C:\\Шлях\\До\\SmartUnrealLocalization.exe",
      "args": ["--mcp"]
    }
  }
}
```

**Claude Code** — одна команда:

```
claude mcp add smart-unreal-localization -- "C:\Шлях\До\SmartUnrealLocalization.exe" --mcp
```

**Codex CLI** — `~/.codex/config.toml`:

```toml
[mcp_servers.smart_unreal_localization]
command = "C:\\Шлях\\До\\SmartUnrealLocalization.exe"
args = ["--mcp"]
```

**Antigravity та інші MCP-клієнти** — додайте локальний (stdio) MCP-сервер з
тією ж командою та аргументом `--mcp` у налаштуваннях MCP клієнта.

Далі просто говоріть з моделлю: *«Відкрий D:\Games\uk\Game.locres і переклади
неперекладені рядки українською»*, *«знайди всі рядки зі словом charge»*,
*«виправ усі проблеми валідації»*, *«увімкни паралельні запити і постав батч
50»*. У моделі 17 інструментів:

- **Рядки**: `get_rows` (посторінкове читання/пошук — регістр, цілі слова,
  regex; рядки містять статус рев'ю і коментарі), `set_translations` (запис
  з валідацією тегів, один крок скасування), `find_replace` (прев'ю →
  застосувати; пише лише в Target, з tag-guard), `get_translation_rules`.
- **Рев'ю**: `set_review` (approved/rejected/none) і `set_comments` — модель
  може перевіряти рядки й позначати чи анотувати їх як живий рецензент.
- **Керування**: `get_status` (з живим прогресом AI-рану та ETA),
  `open_file`, `run_ai_translation` / `stop_ai_translation` (вбудований
  пайплайн, ваш API-ключ), `save_current`, `undo` / `redo`.
- **Налаштування**: `get_settings` / `set_settings` — кожна опція з типом,
  дозволеними значеннями і точним місцем в UI. Єдиний свідомий виняток —
  API-ключ: модель може лише підказати, КУДИ його вставити (Налаштування → AI
  провайдер → API ключ), але не читає й не встановлює його.
- **Діагностика**: `get_logs` (потік вкладки «Журнал»), `get_problems` (знахідки
  валідаторів по рядках), `run_validation` (свіжа перевірка) — модель може
  виправляти позначені рядки сама, часто краще за вбудований автофікс.
- **Контроль якості**: `get_qc_rows`, `submit_qc_verdicts`,
  `get_qc_proposals`, `apply_qc_fixes`, `keep_qc_proposals`,
  `export_qc_report`. Асистент може сам бути рецензентом: забрати рядки, які
  надіслали б перемикачі панелі QC, оцінити їх і надіслати вердикти — за вашу
  підписку в чаті, а не за API-ключ. Його виправлення проходять ту саму локальну
  перевірку, що й вбудована, а ви все одно підтверджуєте кожне через Fix / Keep.
- **Довідка**: `get_app_map` — вбудована карта всього інтерфейсу, тож
  асистент працює як жива документація («що робить «Розгорнути рядки»?», «де «Об'єднати з
  новою версією»?»).

**Політика Translation Memory (безпека):** MCP **ніколи не пише** в TM — ні
власні переклади моделі, ні запущені через MCP AI-рани. Неперевірений
машинний вивід не має тихо забруднювати пам'ять, яка автозаповнює майбутні
переклади; перевірені рядки додавайте самі через ПКМ → *Send to Translation
Memory*. **Читання** TM — ваш явний вибір: якщо для мовної пари TM вже
існує, асистент запитає, використати її чи перекласти з нуля.

Усе, що вона робить, видно наживо в програмі й відкочується Ctrl+Z.
